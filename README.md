# S4.3-R Trader

Windows에서 독립 가동하는 키움 REST API 기반 시스템트레이딩 앱입니다. 자체 Python 환경, 로컬 서버, 한국어 운용 화면, 주문·체결 원장을 사용합니다. 다른 프로젝트나 외부 CDN 없이 실행됩니다.

## 실행

Python 3.11 이상이 필요합니다.

```powershell
git clone https://github.com/hoonoh57/s43r.git
cd s43r
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
.\start.bat
```

브라우저에서 **http://127.0.0.1:8765**를 여세요. 이후에는 `start.bat`으로 실행합니다. 종료는 실행 창에서 Ctrl+C 또는 화면에서 실행 중지·키움 연결 종료 후 `stop.bat`을 사용합니다.

**데모 실행**은 API 키 없이 매수·분할익절·손절·차트·주문/체결 기록을 확인하는 합성 데이터 시뮬레이션입니다. 데모 수익은 실제 투자 성과가 아닙니다.

## 운용 모드

| 모드 | 시세 | 주문 |
|---|---|---|
| 리플레이 | 저장 캔들 / 합성 데모 | 가상 체결 |
| 기록 | 키움 REST / 실시간 시세 | 없음 |
| 페이퍼 | 키움 실시간 시세 | 앱 내부 가상 체결 |
| 키움 모의 | 키움 모의 서버 | 모의 계좌 주문 |
| 실계좌 | 키움 실서버 | 실제 계좌 주문 |

## 키움 연결

1. **연결 · 설정**에서 모드, 종목당 투입액, 최대 종목 수, 총 투입액, 일 손실 한도를 저장합니다.
2. 해당 환경의 App Key와 Secret Key를 입력하고 **키움 연결**을 누릅니다. 선택하면 현재 Windows 계정의 DPAPI로 키를 암호화해 저장합니다. 토큰은 메모리에만 둡니다.
3. 토큰에 연결된 계좌와 잔고 대조 결과를 확인합니다. 실제 계좌번호는 일부만 표시합니다.
4. 조회된 조건식 목록에서 이름을 확인하고 **조건식 구독**을 누릅니다. HTS 조건식 번호와 REST 순번이 같다고 가정하지 않습니다.
5. 당일 진입 대상을 확보하려면 **09:03 전에 연결과 구독을 완료**해야 합니다. 늦게 접속한 경우 과거 포착을 추정하지 않습니다.
6. 시드 준비와 잔고 대조가 끝나면 **자동매매 시작 확인**을 누릅니다. 실계좌는 계좌 끝 4자리를 포함한 확인 문구를 입력해야 합니다.

## 전략

- 09:03 실제 감시 목록을 동결합니다. 이후 실시간 편입·이탈은 기록합니다.
- 완료된 360틱 봉으로 09:04~09:30 진입을 판단합니다.
- 일반 진입 기준선은 09:03 이하 마지막 완료 봉 종가 × 1.055이며, 원본 ST·MACD·JMA·누적대금 조건을 함께 적용합니다.
- 조기가속 예외는 기본 ON입니다. 09:12 이하, 누적대금 15억 이상, MACD 0.20 이상과 셋업 조건에서 +5.5% 이전에도 진입할 수 있습니다.
- 기본 하드스탑 -3%는 **완료 봉 종가 기준**입니다.
- JMA 하락 전환과 수익 조건을 함께 만족하면 원래 수량의 30%씩 분할청산합니다. 정수 수량은 버림합니다.
- BEP, ST/VWAP 이탈, ATR 2.5배 런너 청산, 10:03/10:30 종료 조건을 사용합니다.
- 09:00 이후 실시간 편입형 S4.4-R로 변경한 전략이 아닙니다.

## 주문과 중지

매수는 관측한 최우선 매도호가의 지정가, 전략 청산은 시장가입니다. 접수와 체결을 구분하고 실제 포지션은 주문체결 통지의 누계 수량·금액으로 갱신합니다. 중복 체결 통지와 지연 수수료를 중복 반영하지 않습니다.

- **신규 진입 중지**: 보유분 전략 청산은 계속 감시합니다.
- **전체 중지**: 자동 주문을 멈춥니다. 이미 증권사에 접수된 주문은 남을 수 있습니다.
- **미체결 취소**: 확인된 앱 주문번호의 남은 수량을 취소 요청합니다. 취소 요청 후에도 체결이 발생할 수 있습니다.
- **시세 재동기화**: 자동 주문을 중지하고 30틱/1틱으로 360틱 경계를 다시 확인합니다. 완료 후 다시 시작해야 합니다.
- 일 손실 한도는 실현+평가 손익으로 **신규 진입을 차단**합니다. 강제 일괄청산을 뜻하지 않습니다.

시세 지연, 스프레드·추격 한도 초과, 틱 누락, 연결 단절, 잔고 불일치, 외부 보유/주문, 결과 불명 주문은 운용을 차단합니다. 전용 계좌를 전제로 하며 수동 보유를 자동 인수하지 않습니다. 결과 불명 주문을 자동 재전송하거나 추정 체결로 복구하지 않습니다.

## 캔들 리플레이

**캔들 불러오기**에서 한 거래일의 `s44-audit-batch-v1`/`s44-audit-v1` 360틱 JSON 또는 `date`, `cases` 형식을 읽습니다. 각 case에는 `code`, `name`, `candles`가 필요하고, 각 캔들은 `date`(YYYYMMDD), `time`(HHMM), `open`, `high`, `low`, `close`, `volume`을 포함해야 합니다. 전일 시드와 대상일 캔들을 시간 순서대로 제공하세요.

최대 파일 16 MB, 100종목, 종목당 100,000봉입니다. 공식 사후 MFE를 입력 필터로 사용하지 않습니다. 다만 파일의 종목 목록 자체가 이미 선별된 표본이라면 그 제한은 남습니다. 정수 주수·투입 한도·비용 추정 때문에 거래별 수익률 단순 합계와 금액 결과는 다릅니다. 완료·중지한 마지막 리플레이 결과와 차트는 재시작 후 복원됩니다.

## 저장 위치

- `runtime/trader.sqlite`: 주문·체결·포지션·이벤트 원장
- `runtime/market/*.jsonl`: 수신시각을 포함한 시세·조건·체결 원문
- `runtime/settings.json`: 운용 설정
- `runtime/*.dpapi`: 선택한 경우만 저장하는 암호화 키

`runtime`, 가상환경, 키, 로그는 Git에서 제외됩니다. 원문 체결 기록에는 계좌 정보가 포함될 수 있으므로 공개하지 마세요. 화면의 **실행 보고서 JSON**으로 결과를 내보낼 수 있습니다.

## 검증 범위

로컬 개발 검증에서 자동 테스트 30개와 같은 입력 캔들에 대한 원본 엔진 비교 2,288건을 통과했습니다. Edge에서 데스크톱·모바일, 데모, 차트, 설정, 주문/체결 기록, JSON 다운로드를 확인했습니다.

이 공개 저장소에는 **독립 앱 코드와 사용 안내**를 담았습니다. 기존 프로젝트 전체 박제본과 내부 검증 자료는 포함하지 않았습니다. 해당 로컬 박제본이 없는 환경에서는 원본 대조 테스트 1개가 명시적으로 건너뛰어집니다.

```powershell
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m pytest tests -q
```

`tools/ui_smoke.py`는 로컬 Edge와 8765에서 실행 중인 앱을 사용합니다. 새 데모를 실행하므로 사용자가 리플레이하는 중에 실행하지 마세요. 화면 결과는 `runtime/qa`에 저장됩니다.

**실제 키움 인증·장중 시세·모의/실계좌 체결은 개발 환경에서 실행 검증하지 않았습니다.** 기록·페이퍼·모의 계좌 순서로 확인하세요. REST로 합성한 봉의 경계와 전일 시드는 기존 저장 캔들과 별도 장중 대조가 필요합니다. 확인 불가능한 틱 연결 경계는 운용하지 않습니다. 자동 재접속, 수동 보유 인수, 신용/공매도, NXT/SOR는 포함하지 않습니다. 완료 봉이 없는 거래정지·무체결 상황에서는 즉시 청산을 보장하지 않습니다.
